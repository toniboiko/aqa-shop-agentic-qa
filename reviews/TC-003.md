## Notes (structure and robustness, not REWORK)
1. **Name and price are found separately** (`pages/ShopPage.ts:27-28`). `firstProductName` and `firstProductPrice` are each the first match on the page, not scoped to one product card. The comment at lines 6-7 states the assumption. If a card ever lacks a price, or the order differs, the two could belong to different products. In that case the test fails rather than passing wrongly.
2. **Price pattern repeated** (`pages/CartPage.ts:16` and `pages/ShopPage.ts:19`). The same price regex appears in two Page Objects. That is not a repeat inside one Page Object, just worth knowing.
3. **Processing text** (spec 33-35, `pages/ShopPage.ts:36`):
   - `getByText` with a string ignores case and matches part of the text.
   - The test never checks that the text is absent before the click, so it cannot prove the text appears because of the click.
   - The test case does not require the absence check, so this is minor.
   - Separately, if "Processing..." disappears very quickly, the test may be flaky. That would be a false failure, not a false pass.
4. **"Displayed" in E4** (spec 45). `toHaveText` checks that the element exists and has the right text, not that it is visible. The cart heading check at line 42 and the exact name match make a hidden match very unlikely, but adding `toBeVisible` would match the wording exactly. This is optional.
5. **Comment at line 47** says "Check product price" only, while S6 is "price and name". The name is checked at line 45, so coverage is fine; only the comment is incomplete.
6. **Single-match assumption** (`pages/CartPage.ts:15-17`). The name, price and quantity locators match any h3, any price-like text, and any digits-only text on the cart page. They depend on the cart holding exactly one line. Playwright's single-element check makes the test fail if more than one element matches, so this cannot cause a false pass. It does tie the test to the empty-cart precondition.
